# M2.5 — 后台手动编辑（人工治理闭环）

> **阶段**：Specify（spec.md）⏳ 草案（2026-08-29，待人工 review）
> **上游**：M1 ✅ / M2 ✅；constitution §3.1 将"后台编辑"列入第一阶段范围，M1/M2 均未排期——本里程碑补上这块欠账
> **状态**：草案

---

## 1. 背景与目标

系统数据由 GLM 从论文/网页/资讯自动抽取，错误不可避免（拼错姓名、张冠李戴的机构、幻觉关系）。现有唯一人工治理入口是消歧复核队列（只覆盖"同人合并"一种场景），API 层无任何实体/关系写端点——修正错误只能直连数据库写 SQL。

本里程碑交付**管理员在网页上人工修正与删除数据**的最小完整闭环（实用档，RD-1）：改人、改关系、按人删除、操作日志。同时兑现 docs/07 合规章节的"按人员删除其所有关联数据"承诺。

**成功标志**：管理员不写 SQL 即可修掉一条错名、删掉一条错误关系、按合规要求删除一个学者及其全部关联数据；每一次写操作都留有 before/after 审计记录。

---

## 2. 用户故事

### US-1 修正学者资料
> 作为管理员，我希望在学者详情里直接修正错别字姓名、补充职位/主页/邮箱，让图谱展示正确信息。

### US-2 修正机构归属与研究方向
> 作为管理员，我希望把张冠李戴的机构归属换掉、增删研究方向标签，让筛选和搜索命中正确。

### US-3 删除错误关系
> 作为管理员，我希望删掉 AI 抽错的师生/合作关系（并留原因），且它不会被下一轮管线复活。

### US-4 按人删除（合规）
> 作为管理员，我希望一键删除某学者的全部关联数据（当本人提出删除要求时），论文等公开元数据保留。

### US-5 追溯操作
> 作为管理员，我希望能查到"什么时候把什么从什么改成了什么、为什么改"（单管理员系统，不记操作者，RD-7）。

## 3. 功能需求（EARS）

> 标注：`[Ubiquitous]` 始终 / `[WHEN]` 事件驱动 / `[IF]` 异常处理

### FR-1 学者字段编辑

- **FR-1.1** `[Ubiquitous]` 系统应提供修改 Person 展示字段的端点：姓名、职位（title）、个人主页（homepage）、电子邮箱（email）。改姓名时同步重算 `name_normalized` / 拼音归一。
- **FR-1.2** `[Ubiquitous]` 每次修改应把 before/after 快照与操作原因写入操作日志（FR-6）。
- **FR-1.3** `[IF]` 目标 Person 已被删除或已并入他人（墓碑），系统应拒绝修改并返回明确错误。

### FR-2 机构归属编辑

- **FR-2.1** `[Ubiquitous]` 系统应支持替换/移除 Person 的机构归属，机构**只能从已有 organizations 实体中选择**（搜索选择，不手输新名称，RD-8）。
- **FR-2.2** `[Ubiquitous]` 管理员设定的归属 `person_org.source='admin'`、confidence=1.0；同一机构不重复挂接。

### FR-3 研究方向标签编辑

- **FR-3.1** `[Ubiquitous]` 系统应支持整体替换 Person 的研究方向标签集合（增删改一次提交）。

### FR-4 关系删除与调整

- **FR-4.1** `[Ubiquitous]` 系统应支持删除关系：**墓碑删除**（`deleted_at` + `deleted_reason`），不做物理删除（RD-2）；证据行保留作审计。
- **FR-4.2** `[IF]` 管线后续轮次重新发现同一对人同类型关系，系统应**不复活墓碑关系**（linker/mentor_linker/project_linker 跳过 deleted_at 非空的目标行），证据幂等照旧。
- **FR-4.3** `[Ubiquitous]` 系统应支持人工调整关系强度（strength ∈ [0,1]，带原因），用于降权可疑关系。
- **FR-4.4** `[IF]` 关系已墓碑，系统应拒绝再次删除/调整，返回明确错误。

### FR-5 按人删除（合规级联）

- **FR-5.1** `[Ubiquitous]` 系统应提供按人删除端点（body 带原因），级联处理：
  - Person 置删除墓碑（`deleted_at`）；
  - 其全部关系置墓碑并**删除对应证据行**（合规要求抹除该人关联数据，区别于 FR-4 的保留证据）；
  - 清除其 `person_org` / `person_research_tags` / `paper_authors` 挂接；
  - 其名下 pending 状态的消歧队列条目置取消。
- **FR-5.2** `[Ubiquitous]` 论文（papers）与机构（organizations）实体**不删除**——公开元数据不属于个人关联数据（RD-4）。
- **FR-5.3** `[IF]` 合并/删除后的墓碑 Person，应从图谱、搜索、复核候选、消歧候选中消失（沿用 merged_into 墓碑的过滤面）。

### FR-6 操作日志

- **FR-6.1** `[Ubiquitous]` 上述所有写操作（改字段/换归属/改标签/删关系/调强度/按人删除）应写入 `admin_edits` 表：action、entity_type、entity_id、before(JSON)、after(JSON)、reason、created_at。单管理员内网系统，不设操作者列（RD-7，constitution 排除权限体系）。
- **FR-6.2** `[Ubiquitous]` 系统应提供操作日志查询端点（分页，可按实体过滤）。

### FR-7 前端整合

- **FR-7.1** `[WHEN]` 管理员查看学者详情时，系统应提供"编辑"入口切换表单态，可改姓名/职位/主页/邮箱、换机构归属、改研究方向标签。
- **FR-7.2** `[WHEN]` 管理员查看关系详情（点边）时，系统应提供"删除关系"（必填原因）与"调整强度"操作。
- **FR-7.3** `[Ubiquitous]` 管理页应展示操作日志卡片（最近操作 + 时间 + 原因）。
- **FR-7.4** `[Ubiquitous]` 编辑/删除结果即时反映到图谱、搜索、列表（刷新后可见）；删除的人不再出现。

## 4. 非功能需求

- **NFR-1 幂等**：墓碑关系不因管线重跑复活（双跑幂等测试扩展覆盖）；编辑操作本身可重复提交无副作用（最后写入胜出 + 每次都记日志）。
- **NFR-2 巡检兼容**：C1–C10 巡检在存在墓碑行时应全绿——巡检语义跳过 `deleted_at` 非空的关系/人（C1 计数、C4 唯一性、C6 引用检查均按有效行口径）。
- **NFR-3 零回归**：现有 277 项测试全过，只读 API 行为不变。
- **NFR-4 审计完备**：任何 admin 写端点落库成功 ⟺ 存在对应日志行（单测断言成对出现）。

---

## 5. Out of Scope（本里程碑明确不做）

- ❌ 人工新建关系 / 新建 Person（补漏场景 → 需设计"无证据关系"例外，违背"证据先于关系"原则，暂缓）
- ❌ 误合并的拆分（undo merge）
- ❌ 批量操作、编辑历史回滚 UI
- ❌ 编辑触发自动重算（改机构名不刷关系置信度——RD-3；自动管线拿新证据时自然重算）
- ❌ organizations 实体本身的改名/合并/删除
- ❌ 多用户、权限体系、操作者身份（constitution 排除）
- ❌ 死信重跑 UI、配置 UI（→ M4）

## 6. 验收标准（Acceptance Criteria）

- **AC-1**：改一个错名（含中文名）→ 落库、name_normalized 重算、图谱/搜索刷新后反映新名字、日志含 before/after。
- **AC-2**：换机构归属（从已有实体选择）→ 详情与图谱节点机构更新，person_org.source='admin'。
- **AC-3**：删一条关系（填原因）→ 图谱/列表消失；**重跑对应管线该关系不复活**（双跑断言）；证据行仍在库；日志可查。
- **AC-4**：按人删除 → 该人从图谱/搜索/复核队列消失，其关系全部墓碑且证据行清空，papers 计数不变，C1–C10 全绿。
- **AC-5**：`GET /api/admin/edits` 能按实体过滤出上述全部操作，before/after/reason 完整。
- **AC-6**：前端走查——编辑表单、删除原因输入、强度调整、日志卡片均可用（观感项，用户抽查）。
- **AC-7**：全量测试通过（277 现有零回归 + 新增用例全过）。

## 7. 已确认决策（Resolved Decisions）

- **RD-1（范围档位：实用档）** ✅（2026-08-29 用户确认）：改人字段 + 换机构归属 + 改研究方向 + 删关系/调强度 + 按人删除 + 操作日志；不做人工新建关系、误合并拆分、批量、回滚。
- **RD-2（墓碑删除）**：关系与人的删除均打 `deleted_at` 墓碑而非物理删除——防管线重跑复活（消歧 reject 持久化结论的同一先例），天然留审计痕迹。唯一例外：按人删除时其证据行物理删除（合规抹除）。
- **RD-3（编辑不自动重算）**：字段编辑不触发关系 identity/strength 重算；合并场景重算维持 M1 现状。
- **RD-4（合规删除范围）**：人及其关联数据（关系/证据/归属/标签/作者挂接）删除；论文与机构实体保留（公开元数据）。
- **RD-5（内联编辑，不建独立编辑页）**：编辑入口嵌学者详情面板与边详情面板，日志卡片进管理页——贴合现有三页结构，工作量最小（推翻 docs/05"单独编辑页"构想）。
- **RD-6（admin 命名空间隔离）**：全部写端点挂 `/api/admin/`，前端只读 API 一律不加写能力。
- **RD-7（无操作者列）**：单管理员本地系统（constitution 排除权限体系），日志不记 who。
- **RD-8（机构只选不输）**：机构归属编辑仅限从已有 organizations 搜索选择——规避机构名归一化双函数并存的历史坑（M1 附录 2 教训）。

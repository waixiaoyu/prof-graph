# M3 — 潜在关系挖掘

> **阶段**：Specify（spec.md）⏳ 起草待确认
> **状态**：草案
> **最后更新**：2026-08-31（RD-10：common_network 门槛按生产库探针收紧为 ≥2）

---

## 1. 背景与目标

M1/M2 已建成三种**直接关系**（论文合作 / 学术传承 / 项目合作，均有证据链）。M3 在这张已有网络上跑通三种**潜在关系**发现方法（constitution §3.1）：`common_network`（共同网络）、`research_similarity`（研究方向相似）、`spatiotemporal`（时空重叠），在图谱中以"潜在连接"形式展示，回答"这两个人虽然还没有直接关系，但很可能认识 / 有合作机会"。

**定位边界**：潜在关系是**纯派生数据**——由存量直接关系、研究方向标签、机构归属计算得出，不产生新证据、不写回直接关系表。**零 GLM 调用、零 token 成本**（RD-2）。

**成功标志**：管理员在图谱打开"潜在关系"开关后，能看到虚线连接的潜在人脉；任意一条潜在连接都能点开看到可解释的发现原因（共同合作者是谁 / 重叠的研究方向 / 机构+年份重叠）。

---

## 2. 用户故事

### US-1：发现潜在合作机会
> 作为技术合作经理，我希望看到某位学者的"潜在连接"（尚未直接合作、但通过共同合作者/相近方向/同期同机构推断可能认识的人），以便发现合作引荐机会。

### US-2：理解"为什么是潜在"
> 作为技术合作经理，我希望点击一条潜在连接，看到发现方法、置信度和支撑信号（共同合作者名单、重叠标签、机构与重叠年份），以便判断这条推断是否可信。

## 3. 功能需求（EARS）

> 标注：`[Ubiquitous]` 始终 / `[WHEN]` 事件驱动 / `[IF]` 异常处理。置信度公式数值与阈值均留 plan 定，spec 只锁定结构与口径。

### FR-1 数据模型与迁移

- **FR-1.1** `[Ubiquitous]` 新建 `potential_relationships` 表：person_a_id/person_b_id（**a < b，同 relationships 三保险口径**：代码排序 + CheckConstraint + 唯一键）、discovery_method（common_network / research_similarity / spatiotemporal）、confidence（CHECK 约束在 0.1–0.7，docs/02 口径）、reason（人类可读发现原因）、supporting_signals（JSONB：共同合作者 id 列表 / 重叠标签与相似度 / 机构+重叠年份+粒度）、created_at/updated_at；**UNIQUE(person_a_id, person_b_id, discovery_method)**。存量零迁移。

### FR-2 三种发现方法

- **FR-2.1** `[WHEN]` 重算触发时，系统应基于**活跃直接关系**（relationships 且 deleted_at IS NULL）构建人-人网络，对每对**尚无任何活跃直接关系**的人员对 (A,B)，若**不同共同合作者数 ≥ 2**（初值，依据与实测数字见 RD-10），产出 common_network 潜在关系；supporting_signals 记录共同合作者 person_id 列表与数量。
- **FR-2.2** `[WHEN]` 重算触发时，系统应对双方均有研究方向标签（person_research_tags）的人员对计算标签 Jaccard 相似度；相似度 ≥ 阈值（plan 定，初值 0.3）产出 research_similarity 潜在关系；supporting_signals 记录双方重叠标签与相似度分值。
- **FR-2.3** `[WHEN]` 重算触发时，系统应对**同机构且可证时间重叠**的人员对产出 spatiotemporal 潜在关系。时间信号从两处派生：person_org 行锚定的论文发表年份（person_org.paper_id → papers.published_at）与学术传承关系的 time_start/time_end；**无任何时间证据的同机构对不产出**（宁缺毋滥，RD-4）。supporting_signals 记录机构、机构粒度（org.level）、重叠年份/区间。
- **FR-2.4** `[Ubiquitous]` 同一对人可被多种方法同时命中，各方法独立成行（唯一键含 method）；API 层按 pair 聚合返回（RD-8）。

### FR-3 排除与墓碑口径

- **FR-3.1** `[IF]` 人员对已存在任何**活跃**直接关系（任意 type/subtype），系统不得为其产出潜在关系（已有直接关系 = 潜在失去意义）。
- **FR-3.2** `[IF]` 人员任一端为墓碑（persons.deleted_at 非空或 merged_into_id 非空），或所依据的直接关系为墓碑，该端及其邻接不得参与计算。
- **FR-3.3** `[WHEN]` 重算完成时，引用已删除/已合并人员的存量潜在行、以及后来建立了直接关系的人员对的存量潜在行，应被清除（重算是全量收敛，不是只增不减）。
- **FR-3.4** `[Ubiquitous]` 数据完整性巡检新增检查项（C11）：potential_relationships 每行的两端必须为活跃人、不得存在活跃直接关系、confidence 在界内；违例可被巡检发现。

### FR-4 调度与运行

- **FR-4.1** `[Ubiquitous]` APScheduler 每周日 06:00 全量重算（避开 02:00–05:00 夜链）。
- **FR-4.2** `[Ubiquitous]` 提供 CLI 脚本手动触发重算（沿用 scripts/ 惯例，供验收与补跑）。
- **FR-4.3** `[IF]` 重算过程抛错，系统应整体回滚为重算前状态（潜在关系是派生数据，宁可保留旧版全量也不留半成品）；错误记日志，不写 failed_jobs（无外部依赖调用，无重试语义）。
- **FR-4.4** `[Ubiquitous]` 重算幂等：同输入双跑产出完全相同的行集（沿用 M1 双跑幂等验收惯例）。

### FR-5 API 与前端

- **FR-5.1** `[Ubiquitous]` 图谱 API 应支持独立开关参数 include_potential（默认关）；开启时返回潜在边，按 pair 聚合：{pair, methods: [{method, confidence, reason, signals}]}。潜在边不参与 rel_types 方向筛选（独立维度）。
- **FR-5.2** `[Ubiquitous]` 图谱前端应将潜在连接渲染为可区分的虚线边，并提供与 rel_types 并列的"潜在关系"开关（默认关）；点击潜在边显示发现方法、置信度与支撑信号。
- **FR-5.3** `[Ubiquitous]` 人详情面板应展示该人的潜在连接列表（对方姓名/机构、方法、置信度、原因）；墓碑人不得出现在任何潜在可见面。

## 4. 非功能需求

- **NFR-1** 重算零 GLM 调用、零 token 消耗（RD-2）。
- **NFR-2** 当前生产规模（万级人内、万级直接关系内）全量重算 ≤ 5 分钟（单进程 Python 实现，不引入图数据库/向量库——宪法 §2 技术栈不可漂移）。
- **NFR-3** 全量测试零回归；新增测试覆盖：三方法产出与 signals 可解释性、FR-3 全部排除分支、双跑幂等、API/前端开关与聚合结构、C11 巡检。

## 5. 已解决决策（RD）

- **RD-1（独立表，不进 relationships）**：潜在关系无证据链，不满足"证据先于关系"（constitution §4.2），存独立 potential_relationships 表；docs/02 §4.1 草案结构沿用。不与直接关系混表，也不参与关系强度/消歧体系。
- **RD-2（Jaccard 而非 embedding）**：research_similarity 用标签 Jaccard。理由：① person_research_tags 由 GLM 抽取时已归一为小写英文短语，同义问题在生成端已大幅收敛；② embedding API 不在宪法技术栈，且数千人有调用成本与不确定性；③ 确定性计算可双跑幂等可测试。若上线后实证同义词漏配显著，M4 再评估 embedding 升级（OQ-1 观察）。
- **RD-3（无直接关系才可潜在）**：潜在关系语义 = "尚无直接关系但有信号"；已有直接关系的对产出潜在属噪声，一律排除（FR-3.1）。
- **RD-4（spatiotemporal 时间信号派生 + 宁缺毋滥）**：person_org 无时间列，机构归属时间从锚定论文的发表年份派生（person_org.paper_id → published_at 的年份集合）+ 传承关系 time_start/end；机构粒度权重映射 org.level：lab 1.0 / institute、company 0.6 / university 0.3（docs"同组>同校"的无层级近似）。无时间证据不产出，避免"同机构全连线"的噪声爆炸。
- **RD-5（每周全量重算，不做触发式增量）**：docs 提的"新关系建立即增量重算"不做——周期内陈旧可接受（潜在关系本就定期重算），全量重算实现简单且天然幂等收敛。
- **RD-6（M3 不做潜在关系人工治理）**：潜在关系是纯派生数据，手工删除会被重算复活；"隐藏/降权"语义需要墓碑化改造，归 M4 治理项。M3 仅保证墓碑人/墓碑关系自动排除（FR-3.2/3.3）。
- **RD-7（默认关的独立开关）**：潜在连接默认不在图谱渲染（避免噪声），管理员显式打开；与 rel_types 方向筛选互不影响。
- **RD-8（API 按 pair 聚合）**：同一对多方法命中时 API 返回一个 pair 节点带 methods 数组，前端画一条虚线边、详情列多方法。
- **RD-9（CN 范围天然继承）**：不新增 person 级 CN 判定。直接关系全部产自 CN 范围证据（M1 RD-13 口径），潜在关系在网络内计算即天然在范围内；外国人-外国人潜在对（各经中国学者连接）允许存在，属网络自然产物。
- **RD-10（common_network 门槛 ≥2 个不同共同合作者，2026-08-31 生产库探针实证）**：2884 活跃人 / 8763 活跃直接关系上实测——门槛 ≥1 时净产出 1778 对（83% 候选对本已有直接关系被 FR-3.1 剔除，剩余多为单一高产枢纽辐射的弱信号：一个 50 合作者的教授即可组合出 1200+ 对）；门槛 ≥2 时净产出 43 对，均为"两个不同的人分别连着 A、B 而 A、B 反而无直接关系"的结构性缺口，数量可控且可解释；"强连接变体"（共同者与双方各合作 ≥2 篇）净产出 0——密切合作者的合作者几乎早已直接相连，证明该变体无独立价值。取 ≥2。

## 6. 待解决开放问题（Open Questions）

- **OQ-1**：research_similarity 的 Jaccard 阈值 0.3 在生产数据上的产出量级是否合适（过高→噪声淹没图谱 / 过低→几乎无线）？plan 阶段用生产库离线试算定初值（common_network 已由 RD-10 探针定 2，随网络增长观察量级变化即可）。
- **OQ-2**：spatiotemporal 在当前数据上的真实产出量未知（依赖 person_org 带论文锚点或传承时间的覆盖面）——plan 阶段先跑数据画像，若覆盖率过低（<100 对）考虑降级为"同实验室（webpage 源机构）不限时间"的放宽口径，还是接受少量产出？倾向后者（保持宁缺毋滥）。

## 7. 范围外（Out of Scope）

- ❌ role_match（人↔企业潜在关系，无企业数据源，二期——constitution §3.2）
- ❌ 智能推荐（基于潜在关系主动推荐合作方，二期）
- ❌ embedding 相似度升级（M4 评估项，OQ-1 观察）
- ❌ 潜在关系人工隐藏/删除/降权治理（M4，RD-6）
- ❌ 触发式增量重算（RD-5）
- ❌ 潜在关系进消歧/合并流程（潜在行在重算时按合并后人自动收敛，无需专门处理）

## 8. 验收标准（Acceptance Criteria）

| # | 标准 | 验证方式 |
|---|------|---------|
| AC-1 | fixture 网络上三种方法各产出预期行，supporting_signals 完整可解释（共同合作者名单 / 重叠标签+分值 / 机构+年份+粒度） | 单测 |
| AC-2 | FR-3 全分支：已有直接关系对零产出；墓碑人/墓碑关系邻接不参与；重算后失效存量行被清除 | 单测 |
| AC-3 | 双跑幂等：同输入两次重算行集完全一致 | 单测（沿用 M1 幂等测试惯例） |
| AC-4 | 图谱 API include_potential 开关 + pair 聚合结构正确；前端虚线边渲染、开关、边详情、人详情潜在连接列表可用；墓碑人潜在边不可见 | API 测试 + 前端走查 |
| AC-5 | 生产库实跑一轮：三方法产出 > 0，人工抽 5 条潜在连接核验发现原因真实可解释 | 实跑 + 人工抽查 |
| AC-6 | C1–C10 全绿；新增 C11 巡检全绿；全量测试零回归 | 巡检 + pytest |
| AC-7 | 生产规模重算耗时 ≤ 5 分钟、token 消耗为 0 | 实跑计时 |

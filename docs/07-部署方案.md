# 07-部署方案

## 部署方式：本地部署

### 选择理由

- **数据安全**：所有数据在本地
- **部署简单**：不需要复杂的服务器配置
- **单机使用**：无需考虑多用户并发

---

## 系统架构

```
本地机器
├── PostgreSQL 数据库（本地安装或 Docker）
├── Python 后端服务（FastAPI）
├── React 前端（静态文件）
└── 定时任务脚本（数据更新）
```

---

## 数据更新机制

### 两种触发方式

#### 1. 自动更新

- **使用系统定时任务**（如 cron 或 Windows 任务计划）
- **时间**：每天凌晨自动执行
- **流程**：获取 → 抽取 → 入库 → 更新关系

#### 2. 手动触发

- 在管理后台提供"立即更新"按钮
- 实时显示更新进度
- 更新完成后刷新数据

---

## 运行环境要求

### 最低配置

| 资源 | 要求 | 说明 |
|-----|------|------|
| **CPU** | 4 核心以上 | 用于 GLM 调用和数据处理 |
| **内存** | 8GB 以上 | 用于数据库和缓存 |
| **存储** | 50GB 以上 | 用于数据库 + 论文缓存 |
| **网络** | 稳定的网络连接 | 用于调用 GLM API |

### 软件依赖

- **Python 3.10+**
- **Node.js 18+**（前端构建）
- **PostgreSQL 14+**
- **浏览器**：Chrome/Edge/Firefox 最新版

---

## 系统组件

### 后端服务

- **框架**：FastAPI（Python）
- **功能**：API服务、数据处理、GLM调用
- **端口**：8000（默认）

### 前端服务

- **框架**：React
- **构建**：静态文件，通过 nginx 或直接提供服务
- **端口**：3000（开发）/ 80/443（生产）

### 数据库

- **类型**：PostgreSQL
- **端口**：5432（默认）

---

## 环境变量配置

### GLM API 配置

```bash
# GLM API 配置
GLM_CODING_API_KEY=your_glm_api_key
GLM_CODING_MODEL=glm-5.2
GLM_CODING_ANTHROPIC_API_URL=https://open.bigmodel.cn/api/anthropic/v1/messages

# 或者使用通用环境变量
LLM_API_KEY=your_glm_api_key
LLM_MODEL=glm-5.2
LLM_API_URL=https://open.bigmodel.cn/api/anthropic/v1/messages

# 请求控制
LLM_REQUEST_TIMEOUT_MS=600000
LLM_MAX_OUTPUT_TOKENS=12000
```

### 数据库配置

```bash
# PostgreSQL 配置
DATABASE_URL=postgresql://user:password@localhost:5432/prof_graph
POSTGRES_USER=your_user
POSTGRES_PASSWORD=your_password
POSTGRES_DB=prof_graph
```

### 服务配置

```bash
# 后端服务配置
PORT=8000
HOST=127.0.0.1

# 前端服务配置
REACT_APP_API_URL=http://localhost:8000
```

## 定时任务配置

### Linux/macOS（cron）

```bash
# 每天凌晨 2 点执行数据更新
0 2 * * * /usr/bin/python3 /path/to/update_script.py
```

### Windows（任务计划）

1. 打开"任务计划程序"
2. 创建基本任务
3. 设置触发器：每天凌晨 2 点
4. 设置操作：运行 Python 脚本

## 数据管理

### 数据备份

虽然系统不强制要求备份机制，但建议定期备份数据库：

```bash
# PostgreSQL 备份
pg_dump -U user -d prof_graph > backup_$(date +%Y%m%d).sql
```

### 数据恢复

```bash
# PostgreSQL 恢复
psql -U user -d prof_graph < backup_20260811.sql
```

## 常见问题

### Q1: GLM API 调用失败

**检查**：
1. API Key 是否正确配置
2. 网络连接是否正常
3. API 端点是否正确

### Q2: 数据库连接失败

**检查**：
1. PostgreSQL 服务是否运行
2. 数据库配置是否正确
3. 端口是否被占用

### Q3: 前端无法连接后端

**检查**：
1. 后端服务是否运行
2. API URL 是否正确
3. 端口是否正确

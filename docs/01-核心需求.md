# 01-核心需求

## 项目概述

### 项目名称

**基于本体的学术合作知识图谱系统**

### 项目定位

本系统是一个基于公开信息的学术合作关系自动发现与维护系统，通过知识图谱技术对高校老师、企业、项目等合作资源进行结构化管理。

系统核心价值在于：
- 用间接手段或推导方法发现直接关系
- 为每种关系提供专门的置信度评估
- 积累合作方之间的关系网络，为未来挖掘校企合作方提供候选参考

---

## 核心价值定位

### 核心问题

**传统痛点：人工识别合作关系，费时费力且难维护**

- 合作资源信息分散在论文、新闻、网站等多个数据源
- 人工刷新闻、看论文、扒网站 → 手动记录关系
- 信息更新频繁，依赖人工维护，成本高且易遗漏

### 系统定位

**基于公开信息的校企合作关系自动发现与维护系统**

通过 AI 自动化技术，对高校老师与企业之间的合作关系进行：
- 自动发现：从公开数据源中持续监控并发现新关系
- 自动抽取：识别实体（人员、机构、企业）及其关系
- 自动维护：关系发生变化时自动更新，无需人工干预

### 核心价值

> **积累合作方之间的关系网络，为未来挖掘校企合作方提供候选参考**

帮助用户：
- 看清楚某领域内的校企合作网络
- 找到与现有合作网络有关联的目标合作方候选
- 持续跟踪关系变化，自动发现新的合作机会

## 目标用户与场景

### 目标用户

**主要用户**：技术合作经理、科研管理人员

### 核心场景

**校企合作（产学研合作）**：
- 寻找某领域的专家与企业进行合作
- 了解学校老师在外部的合作情况
- 评估企业与高校的合作关系网络

## 第一阶段范围界定

### 第一阶段功能定位

**核心目标**：关系的自动发现和维护

**优先级排序**：
1. 🔥 **关系自动发现与维护**（第一阶段核心）
2. 🔥 **图谱可视化**（让人看清楚关系网络）
3. ⏳ **智能推荐**（后续迭代）
4. ⏳ **AI知识问答**（后续迭代）

### 第一阶段不包含

- ❌ 推荐系统（找最合适的合作方）
- ❌ AI 问答（自然语言查询）
- ❌ 关系强度评分与排序
- ❌ 高校官网爬取（留到第二阶段）
- ❌ 智能推荐（后续迭代）
- ❌ AI 问答（后续迭代）
- ❌ 企业关系（第二阶段）

### 第一阶段重点是

- 接入 2-3 个核心数据源
- 实现实体和关系的自动抽取
- 建立基础图谱存储和可视化
- 让用户能够看清关系网络的全貌

## 核心设计理念

### 设计理念 1：以人为中心

> **系统核心主键：人（合作方）**

**设计原则**：
- Person（合作方）是中心实体
- 其他实体（Organization、Paper）围绕合作关系展开
- 关系网络以"人"为中心进行构建和展示

**数据视角**：
- 不是"论文有哪些作者"
- 而是"这个人发表了哪些论文、与哪些人有合作关系"

### 设计理念 2：知识图谱思维

> **这是一张知识图谱，而不仅仅是关系数据库**

**传统关系数据库 vs 知识图谱**：

| 传统关系数据库 | 知识图谱 |
|---------------|---------|
| 表内关系（外键） | 关系本身是实体 |
| Person → Paper | Person ←[合作关系]→ Person |
| 关系是结构化的 | 关系有**证据、属性、语义** |
| 表关系的"原因"不存储 | 关系的"为什么"是核心 |

### 设计理念 3：关系结果与挖掘手段的区分

> **关系结果：都是直接关系（A ⇄ B）**  
> **挖掘手段：用间接手段或推导方法发现直接关系**

## 第一阶段 MVP 功能清单

### 核心功能（全部必须）

| 功能模块 | 说明 | 技术实现 |
|---------|------|---------|
| **论文数据获取** | 从 arXiv API 定期获取论文 | Python 脚本 + 定时任务 |
| **资讯搜索** | 简单的网络资讯搜索作为信息源头 | 搜索引擎 API + 内容解析 |
| **实体识别** | GLM 抽取作者、机构、研究方向 | GLM-5.2 实体识别调用 |
| **关系抽取** | 建立论文合作、同机构关系 | 基于实体自动推导 |
| **证据链处理** | 先有证据→识别关系→提取保存证据 | 证据表存储追溯 |
| **数据存储** | PostgreSQL 存储所有实体和关系 | 数据库 Schema 设计 |
| **图谱可视化** | React + 图谱组件展示关系网络 | React Flow / Cytoscape.js |
| **搜索功能** | 按姓名、机构、研究方向搜索 | PostgreSQL 全文搜索 |
| **手动编辑** | 人工修正实体和关系 | React 编辑界面 |

## 关系类型总结

### 第一阶段挖掘的4种直接关系

| 关系类型 | 说明 | 挖掘手段 | 价值 |
|---------|------|---------|------|
| **论文合作关系** | 共同发表过论文 | 从论文数据库直接获取 | ⭐⭐⭐ 核心 |
| **项目合作关系** | 共同参与过项目 | 从多个资讯源推断 | ⭐⭐⭐ 核心 |
| **师兄弟关系** | 同一实验室的同学、师生关系 | 从多种数据源推导 | ⭐⭐⭐ 核心 |
| **顾问关系** | 担任某机构的技术顾问、学术顾问 | 从资讯中提取 | ⭐⭐ 重要 |

### 明确排除的关系类型

- ❌ 企业相关关系（企业不是学术合作方）
- ❌ 实习指导关系（重点关注博士生与导师的指导关系，已包含在师兄弟关系中）

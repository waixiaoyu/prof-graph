# 02-数据模型设计

## 核心设计理念

### 知识图谱视角

> **这是一张知识图谱，而不仅仅是关系数据库**

**关键特性**：
- 关系本身是实体，有独立的属性和证据
- 每个关系都必须有明确的证据链，确保可信度
- 关系的"为什么"是核心，支持追溯和验证

---

## 实体模型设计

### Person（人员/合作方）

**核心字段**：
| 字段名 | 说明 | 数据来源 |
|-------|------|---------|
| 姓名 | 中文姓名/英文姓名 | 论文作者、教师主页 |
| 机构 | 所属高校/院系 | 论文署名单位、主页 |
| 研究方向 | 技术领域标签（多标签） | 论文关键词、主页声明 |

**扩展字段**：
| 字段名 | 说明 | 数据来源 |
|-------|------|---------|
| 职位/职称 | 教授/副教授/讲师 | 教师主页 |
| 联系方式 | 邮箱/电话 | 教师主页 |
| 个人简介 | 研究背景描述 | 教师主页 |
| 个人主页 | 教师/学者主页 URL | 教师/学者主页 |

**研究方向表示**：
- 使用多标签字段，如：["深度学习", "计算机视觉", "NLP"]
- 支持多个研究方向的同时表达

### Organization（机构）

| 字段名 | 说明 | 第一阶段 |
|-------|------|---------|
| 名称 | 高校/院系/实验室名称 | ✅ 必须 |
| 层级 | 校级/院级/实验室 | ✅ 必须 |
| 官网 | 机构主页 URL | □ 可选 |
| 地点 | 国家/城市 | □ 可选 |

**层级说明**：
- 校级：如"清华大学"
- 院级：如"清华大学计算机系"
- 实验室级：如"清华大学知识工程实验室"

### Paper（论文）

| 字段名 | 说明 | 第一阶段 |
|-------|------|---------|
| 标题 | 论文标题 | ✅ 必须 |
| 作者 | 作者列表（关联 Person） | ✅ 必须 |
| 机构 | 署名机构（关联 Organization） | ✅ 必须 |
| 发布时间 | 发表年份 | ✅ 必须 |
| 来源 | 会议/期刊（如 NeurIPS/ICML） | □ 可选 |
| 摘要 | 论文摘要 | □ 可选 |
| 关键词 | 研究方向标签 | ⭐ 重要 |

## 关系模型设计

### 关系分类

**表内关系（传统外键关系）**：
- Person ↔ Paper（作者-发表-论文）
- Person ↔ Organization（作者-任职-机构）
- Paper ↔ Organization（论文-署名-机构）

**表外关系（知识图谱核心）**：
- Person ↔ Person（合作关系）⭐
  - 第一阶段包含4种直接关系：论文合作、项目合作、师兄弟关系、顾问关系

### 关系的"证据链"设计

> **知识图谱的核心是回答"为什么"**

- 为什么 A 和 B 是合作关系？ → 因为他们共同发表了论文 X、Y、Z
- 为什么 A 和 C 是潜在合作关系？ → 因为他们都与 B 有合作关系，且研究方向相似

### 关系属性设计

**每个关系必须包含**：

| 属性 | 说明 | 示例 |
|-----|------|-----|
| **关系类型** | 论文合作/项目合作/师兄弟/顾问 | "论文合作" |
| **证据列表** | 支撑该关系的证据对象 | [Paper1, Paper2, ...] 或 [Organization1] |
| **证据描述** | 人类可读的证据说明 | "基于论文：《Attention Is All You Need》等 3 篇" |
| **时间信息** | 关系的时间范围 | "2018-2024" 或 "最近合作：2024年" |
| **置信度** | AI 抽取的可靠性 | 0.95 |

### 证据链设计原则

> **每个关系都必须有明确的证据链，确保可信度**

**证据链示例**：

```
关系：张教授 —— 李教授
类型：论文合作
证据：
  - 论文：《Attention Is All You Need》（2018，NeurIPS）
  - 论文：《BERT: Pre-training of Deep Bidirectional Transformers》（2019，NAACL）
  - 论文：《GPT-3: Language Models are Few-Shot Learners》（2020，NeurIPS）
证据描述：基于 3 篇合作论文，最近合作于 2020 年
置信度：1.0（基于明确的论文数据）
```

**同机构关系示例**：

```
关系：王教授 —— 赵教授
类型：同机构关系
证据：
  - 机构：清华大学计算机系（从两人多论文署名单位推断）
证据描述：两人在多篇论文中均署名"清华大学计算机系"
置信度：0.8（基于推断）
```

### 设计原则

1. **所有关系必须有证据**：无证据的关系不存储
2. **证据必须是可追溯的**：证据对象本身存在于数据库中
3. **关系类型明确区分**：不同类型的关系有不同的语义
4. **置信度标注**：AI 抽取的关系必须标注可信度

## 数据库 Schema 设计

### 核心表结构

#### 1. persons（人员表）

```sql
CREATE TABLE persons (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    organization_id INTEGER REFERENCES organizations(id),
    research_tags TEXT[], -- 多标签研究方向
    position VARCHAR(50), -- 职位/职称
    contact_info TEXT, -- 联系方式
    bio TEXT, -- 个人简介
    homepage_url VARCHAR(500), -- 个人主页
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

#### 2. organizations（机构表）

```sql
CREATE TABLE organizations (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    level VARCHAR(20), -- 'university'/'department'/'lab'
    website_url VARCHAR(500),
    location VARCHAR(100),
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### 3. papers（论文表）

```sql
CREATE TABLE papers (
    id SERIAL PRIMARY KEY,
    title TEXT NOT NULL,
    publish_year INTEGER,
    source VARCHAR(200), -- 会议/期刊名称
    abstract TEXT,
    keywords TEXT[],
    doi VARCHAR(100),
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### 4. relationships（关系表）

```sql
CREATE TABLE relationships (
    id SERIAL PRIMARY KEY,
    person1_id INTEGER REFERENCES persons(id),
    person2_id INTEGER REFERENCES persons(id),
    relationship_type VARCHAR(50) NOT NULL, -- 'paper_cooperation'/'project_cooperation'/'academic_siblings'/'advisor'
    confidence FLOAT DEFAULT 1.0,
    time_range VARCHAR(50), -- 如 "2018-2024"
    latest_evidence_time TIMESTAMP,
    evidence_description TEXT,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(person1_id, person2_id, relationship_type)
);
```

#### 5. evidence（证据表）

```sql
CREATE TABLE evidence (
    id SERIAL PRIMARY KEY,
    relationship_id INTEGER REFERENCES relationships(id),
    evidence_type VARCHAR(50) NOT NULL, -- 'paper'/'organization'/'news'/'project'
    evidence_id INTEGER NOT NULL, -- paper_id 或 organization_id
    evidence_description TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);
```

#### 6. person_paper_affiliation（作者-论文-机构关联表）

```sql
CREATE TABLE person_paper_affiliation (
    id SERIAL PRIMARY KEY,
    person_id INTEGER REFERENCES persons(id),
    paper_id INTEGER REFERENCES papers(id),
    organization_id INTEGER REFERENCES organizations(id),
    author_order INTEGER, -- 作者顺序
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(person_id, paper_id, organization_id)
);
```

### 设计说明

1. **证据单独存储**：证据表记录每个关系的具体证据，支持追溯和查询
2. **关系唯一性**：通过 UNIQUE 约束确保相同两人、相同类型的关系只存一条
3. **时间信息**：关系表记录时间范围和最新证据时间
4. **灵活的标签存储**：使用 TEXT[] 存储多标签（研究方向、关键词）

## 证据链处理逻辑

### 正确的流程

> **先有证据 → 识别关系 → 提取保存证据**

### 流程说明

```
原始数据（论文、资讯）
  ↓
【证据提取】保存原始证据对象
  ↓
【实体识别】GLM 识别人员、机构
  ↓
【关系识别】基于证据识别关系类型
  ↓
【关系存储】建立关系 + 关联证据
```

### 数据库逻辑

1. **先存证据**：论文、资讯作为独立实体存入数据库
2. **再识关系**：基于证据实体识别人员之间的关系
3. **关联证据**：关系表关联证据表，支持追溯

### 示例流程

```
1. 获取论文《Attention Is All You Need》
   → 存入 papers 表（id=1）

2. GLM 识别实体
   → 识别出作者：Ashish Vaswani, ...
   → 识别出机构：Google Brain

3. 建立关系
   → 发现 Ashish Vaswani 与其他作者有合作关系
   → 存入 relationships 表

4. 关联证据
   → 存入 evidence 表，关联 paper_id=1
   → 支持追溯："为什么他们是合作关系？因为共同发表了这篇论文"
```

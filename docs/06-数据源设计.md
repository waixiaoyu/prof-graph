# 06-数据源设计

## 核心分类约定 ⭐

> 本文档统一约定数据源的两类技术形态：
>
> | 类别 | 第一阶段 | 说明 |
> |------|---------|------|
> | **RSS 订阅** | ✅ 纳入 | 结构化（XML），解析简单，无反爬 |
> | **网页爬虫** | ⏳ 第二阶段 | 非结构化，需处理反爬、登录、动态加载 |
>
> **唯一例外**：**高校官网爬取纳入第一阶段**。理由：它是学术传承关系的唯一可靠数据源（导师主页学生列表、实验室成员名单、毕业生名单、论文致谢），且技术难度低、反爬少。商业科技媒体（36氪/虎嗅/钛媒体/企业官网）等爬虫留到第二阶段。

## 第一阶段数据源策略

### 优先实现

#### 1. 论文数据库（arXiv RSS）

- **结构化程度高**，RSS 订阅即可
- **可抽取**：作者、机构（需 GLM/外部 API 补全）、合作关系、研究方向
- **服务关系**：论文合作关系 `paper_cooperation` 的核心来源
- **自动化难度**：相对较低

#### 2. RSS 资讯订阅（AI 媒体）

- **结构化程度高**，RSS/XML 格式
- **可抽取**：新闻标题、摘要、正文、链接
- **服务关系**：项目合作关系 `project_cooperation` 的主要来源（从资讯中推断共同参与项目）
- **自动化难度**：低

#### 3. 高校官网爬取（教师主页、院系网站、实验室页面）⭐特例纳入第一阶段

- **结构相对规整**，爬取难度低
- **可抽取**：教师信息、研究方向、联系方式、**导师学生列表、实验室成员名单、毕业生名单、论文致谢**
- **服务关系**：**学术传承关系 `academic_mentorship` 的唯一可靠数据源**
- **自动化难度**：低到中等

### 暂缓实现（第二阶段）

- **商业科技媒体爬取**（36氪/虎嗅/钛媒体/企业官网）：价值高但反爬、登录、动态加载等处理复杂，建议后续通过专业 API 或服务解决
- **企业数据源**：顾问关系、校企合作 role_match 等需要企业实体支撑的关系

## RSS 资讯功能设计

### 功能定位

**RSS 订阅作为第一阶段项目合作关系的信息源头**（爬虫类不在第一阶段）

### 技术实现

| 方案 | 第一阶段 | 说明 | 难度 |
|-----|---------|------|------|
| **RSS 订阅** | ✅ 是 | 使用标准 RSS 格式订阅 AI 媒体 | 低 |
| **搜索引擎 API** | ❌ 否 | 使用 Google/Bing API 搜索相关资讯 | 中 |
| **网页爬虫** | ❌ 否 | 爬取非 RSS 来源的资讯 | 高 |

### 推荐方案

**RSS 订阅 + GLM 内容解析**
- 订阅主要 AI 媒体的 RSS（机器之心、新智元、量子位、arXiv News 等）
- APScheduler 定期获取新资讯
- GLM 解析资讯中的实体和关系（项目参与、人员变动等）
- 建立资讯作为证据的关联关系（项目合作关系）

## 数据更新机制

### 更新频率

**每天更新一次**

### 触发方式

#### 1. 自动更新

- **时间**：每天凌晨自动执行
- **范围**：抓取前一天的新论文和资讯
- **流程**：获取 → 抽取 → 入库 → 更新关系

#### 2. 手动触发

- 在管理后台提供"立即更新"按钮
- 实时显示更新进度
- 更新完成后刷新数据

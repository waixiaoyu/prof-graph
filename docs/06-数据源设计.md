## 第一阶段数据源策略

### 优先实现

#### 1. 论文数据库（ArXiv、Google Scholar等）

- **结构化程度高**，有成熟 API
- **可抽取**：作者、机构、合作关系、研究方向
- **自动化难度**：相对较低

#### 2. RSS资讯订阅

- **结构化程度高**，RSS/XML 格式
- **可抽取**：新闻标题、摘要、链接
- **自动化难度**：低

#### 3. 高校官网（教师主页、院系网站）

- **结构相对规整**，爬取难度低
- **可抽取**：教师信息、研究方向、联系方式
- **自动化难度**：低到中等

### 暂缓实现

- **新闻/资讯**：虽然价值高，但爬取和结构化难度极高，建议后续通过专业 API 或服务解决

## 网络资讯搜索功能设计

### 功能定位

**简单的网络资讯搜索作为第一阶段信息源头**

### 技术实现

| 方案 | 说明 | 难度 |
|-----|------|------|
| **RSS 订阅** | 使用标准 RSS 格式订阅 | 低 |
| **搜索引擎 API** | 使用 Google/Bing API 搜索相关资讯 | 中 |
| **关键词监控** | 监控特定关键词的资讯更新 | 中 |

### 推荐方案

**RSS 订阅 + 简单内容解析**
- 订阅主要科技媒体的 RSS（如 36氪、机器之心等）
- 定期获取新资讯
- GLM 解析资讯中的实体和关系
- 建立资讯作为证据的关联关系

## 数据更新机制

### 更新频率

**每天更新一次**

### 触发方式

#### 1. 自动更新

- **时间**：每天凌晨自动执行
- **范围**：抓取前一天的新论文和资讯
- **流程**：获取 → 抽取 → 入库 → 更新关系

#### 2. 手动触发

- 在管理后台提供"立即更新"按钮
- 实时显示更新进度
- 更新完成后刷新数据

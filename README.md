# 企业级学术网络治理系统

## 项目概述

本系统是一个基于公开信息的**学术人脉网络自动发现与治理系统**，通过知识图谱技术对高校老师、企业、项目等合作资源进行结构化管理。

**核心定位**：用 AI 自动化技术挖掘学术人脉关系，构建可追溯、可评估的人脉网络图谱，为校企合作的决策提供数据支撑。

**应用聚焦**：虽然系统专注于学术人脉网络的挖掘，但主要应用场景聚焦于校企合作、产学研合作、人才引进等实际业务场景。

---

## 核心价值：人脉网络的可视化与治理

### 1. 自动发现学术人脉

> **从公开信息中挖掘隐藏的人脉关系**

- **传统方式**：人工查找论文、新闻、项目信息 → 手动记录人脉关系
- **我们的方式**：AI 自动分析公开信息 → 自动发现和更新人脉网络

**价值体现**：
- 节省 90% 以上的人工查找时间
- 发现人工难以察觉的人脉连接
- 持续监控人脉网络变化

### 2. 可追溯的人脉证据

> **每条人脉关系都有明确的证据支撑**

- **传统系统**：只存储关系，不记录证据
- **我们的方式**：每条人脉关系都关联证据链，可追溯验证

**价值体现**：
- 人脉关系可靠性高，有据可查
- 支持人工审核和修正
- 增强决策的可信度

### 3. 智能人脉质量评估

> **为人脉关系提供专门的质量评估**

- **传统系统**：二元的"认识/不认识"
- **我们的方式**：多维度的置信度评估，量化人脉关系质量

**价值体现**：
- 区分人脉关系强度，优先关注高质量人脉
- 降低决策风险
- 支持过滤和排序

### 4. 结构化的人脉网络

> **以人为中心的学术人脉网络**

- **传统方式**：人脉信息分散在 Excel、文档、邮件中
- **我们的方式**：以人为中心，全面展示人脉关系网络

**价值体现**：
- 一目了然的人脉网络
- 发现潜在的人脉连接和机会
- 支持多维度人脉分析

### 5. 潜在关联的智能挖掘 ⭐核心价值

> **从非直接信息中发现潜在的人脉关联**

- **传统方式**：只能看到显性的直接关系，无法发现潜在连接
- **我们的方式**：AI 智能分析多源信息，挖掘潜在的人脉关联

**核心技术挑战**：
- 潜在信息关联的挖掘和匹配是系统最具挑战性的部分
- 需要从论文、项目、机构等多维度信息中推断潜在关系
- 通过共同合作者、研究兴趣相似性、时空重叠等信号进行匹配

**价值体现**：
- 发现人工难以察觉的潜在人脉机会
- 为校企合作方推荐提供高质量候选
- 突破显性关系的局限，挖掘隐性价值

**技术实现**：
- 基于图算法的潜在关系发现（如：共同邻居、路径分析）
- 多维度特征匹配（研究方向、地理位置、时间窗口）
- 置信度评分机制（综合多个信号评估关联强度）

## 核心功能

### 第一阶段功能（MVP）

| 功能 | 说明 | 技术实现 |
|-----|------|---------|
| **论文数据获取** | 从 arXiv RSS 跨大类采集 18 个分类，AI 相关性过滤后仅保留含 AI 成分的论文（RD-1） | Python 脚本 + APScheduler 定时任务 |
| **资讯获取** | 通过 RSS 订阅获取相关资讯（机器之心/新智元/量子位等） | RSS 解析 + 内容分析 |
| **高校官网爬取** | 抓取教师主页/实验室成员/毕业生名单（学术传承关系核心来源） | 针对性爬虫（特例纳入第一阶段） |
| **实体识别** | GLM 自动抽取作者、机构、研究方向 | GLM-5.2 API |
| **关系抽取** | 建立 3 种直接关系（论文合作、项目合作、学术传承） | 基于实体自动推导人脉关系 |
| **证据链处理** | 为每个关系建立证据链 | 证据表存储追溯 |
| **图谱可视化** | 支持大规模节点的交互式图谱展示 | React Flow（RD-3 锁定） |
| **搜索/筛选** | 姓名/机构输入框 + 业务方向/学术赛道预设筛选器（无自由文本方向搜索，RD-7） | PostgreSQL 查询 + 配置驱动筛选 |
| **手动编辑** | 人工修正实体和关系 | React 编辑界面 |

### 后续迭代功能

- 智能推荐：基于关系网络推荐潜在合作方
- AI 问答：自然语言查询关系网络
- 企业关系挖掘：包括顾问关系、校企潜在合作（role_match）
- 商业科技媒体爬取：36氪/虎嗅/企业官网等
- 动态监控：实时关系变化提醒

## 技术先进性

### 1. 知识图谱 + 人脉网络建模

**创新点**：以人为中心的人脉网络建模

- 以"人"为中心实体，其他实体围绕展开
- 人脉关系本身是实体，有独立的属性和证据
- 支持 3 种专门的直接关系类型（论文合作、项目合作、学术传承），每种都有专门的置信度评估

**技术优势**：
- 人脉关系可追溯、可验证
- 支持复杂的网络分析
- 灵活的关系类型扩展

### 2. GLM 驱动的智能抽取

**创新点**：使用 GLM-5.2 进行全量实体和关系抽取

- 每篇论文都调用 GLM 进行实体识别和关系抽取
- 支持 3 种专门的关系抽取模式
- 输出结构化的 JSON 数据

**技术优势**：
- 准确度远高于传统规则方法
- 处理复杂的语义关系
- 支持多语言、多格式

### 3. 多维度置信度评估

**创新点**：每种关系都有专门的置信度计算方式

- **论文合作**：基于姓名确信度和机构确信度
- **项目合作**：基于信息明确性、充分性、可访问性
- **学术传承关系**：基于数据源可信度、关系推断确定性、同机构粒度

**技术优势**：
- 量化关系可靠性
- 支持过滤和排序
- 降低决策风险

### 4. 证据链追溯机制

**创新点**：先有证据 → 识别关系 → 提取保存证据

- 每个关系都关联证据列表
- 支持证据的可追溯性
- 提供人类可读的证据描述

**技术优势**：
- 关系可靠性高
- 支持人工审核
- 增强决策可信度

## 目标用户

### 主要用户

- **技术合作经理**：寻找校企合作方，评估合作潜力，了解学术人脉
- **科研管理人员**：了解学术人脉网络，分析合作动态
- **高校研究人员**：发现潜在合作伙伴，了解研究人脉

### 使用场景

**场景 1：寻找某领域的专家人脉**
- 输入：业务方向/学术赛道筛选器（如 ADN、Network Autonomy）
- 输出：该领域的专家列表 + 研究方向 + 人脉关系

**场景 2：了解专家的人脉网络**
- 输入：专家姓名
- 输出：该专家的人脉关系列表 + 合作论文 + 证据链

**场景 3：发现潜在人脉连接**
- 输入：当前人脉网络
- 输出：潜在人脉连接候选 + 置信度评估

## 技术架构

### 技术栈

| 组件 | 技术选型 | 说明 |
|-----|---------|------|
| **数据库** | PostgreSQL | 成熟稳定，支持 JSON 类型 |
| **后端框架** | FastAPI（Python） | 轻量高效，适合 AI 集成 |
| **前端框架** | React | 组件化开发，生态丰富 |
| **图谱可视化** | React Flow（RD-3 锁定） | 支持大规模节点展示 |
| **AI 引擎** | GLM-5.2 API | 实体识别、关系抽取 |

### 系统架构

```
数据源层：论文数据库、RSS 资讯、高校官网
    ↓
AI 处理层：GLM 实体识别、人脉关系抽取、置信度评估
    ↓
知识图谱层：PostgreSQL（实体 + 关系 + 证据）
    ↓
服务层：FastAPI 后端服务
    ↓
展示层：React 前端 + 人脉图谱可视化
```

## 开发方式：Spec-Driven Development（SDD）

本项目采用规格驱动开发，**`specs/` 目录是唯一实现依据**，`docs/` 仅为设计参考资料（两者冲突时以 `specs/` 为准）。

```
specs/
├── README.md                       ← 里程碑导航 + 进度板
├── .specify/memory/constitution.md ← 项目级硬约束（技术栈、范围边界、术语）
├── M1-paper-cooperation-pipeline/  ← 论文合作全链路（当前焦点）
├── M2-academic-mentorship-and-project/ ← 学术传承 + 项目合作
├── M3-potential-relationships/     ← 潜在关系挖掘
└── M4-stability-and-polish/        ← 稳定性与体验打磨
```

每个里程碑严格四阶段推进，阶段间人工 review：**spec.md（做什么）→ plan.md（怎么做）→ tasks.md（按什么顺序）→ implement（代码）**。

当前进度与技术决策记录（RD-1~RD-12）详见 [specs/README.md](./specs/README.md)。

> 项目尚处设计阶段，暂无代码——快速开始将在 M1 implement 后补充。

# 企业级学术网络治理系统

## 项目概述

本系统是一个基于公开信息的学术合作关系自动发现与维护系统，通过知识图谱技术对高校老师、企业、项目等合作资源进行结构化管理。

**核心定位**：用 AI 自动化技术挖掘学术合作关系，构建可追溯、可评估的知识图谱，为校企合作的决策提供数据支撑。

---

## 核心价值

### 1. 自动发现合作关系

> **用间接手段挖掘直接关系**

- **传统方式**：人工查找论文、新闻、项目信息 → 手动记录关系
- **我们的方式**：AI 自动分析公开信息 → 自动发现和更新关系

**价值体现**：
- 节省 90% 以上的人工查找时间
- 持续监控关系变化，自动发现新关系
- 避免人工维护的信息遗漏和滞后

### 2. 可追溯的证据链

> **每个关系都有明确的证据支撑**

- **传统系统**：只存储关系，不记录证据
- **我们的方式**：每个关系都关联证据链，可追溯验证

**价值体现**：
- 关系可靠性高，有据可查
- 支持人工审核和修正
- 增强决策的可信度

### 3. 智能置信度评估

> **为每种关系提供专门的置信度计算**

- **传统系统**：二元的"有关系/无关系"
- **我们的方式**：多维度的置信度评估，量化关系可靠性

**价值体现**：
- 区分关系可靠性，优先关注高置信度关系
- 降低决策风险
- 支持过滤和排序

### 4. 结构化的学术网络

> **以人为中心的学术合作关系网络**

- **传统系统**：实体分散，关系不可见
- **我们的方式**：以人为中心，全面展示合作关系网络

**价值体现**：
- 一目了然的合作网络
- 发现潜在的连接和机会
- 支持多维度分析和探索

## 核心功能

### 第一阶段功能（MVP）

| 功能 | 说明 | 技术实现 |
|-----|------|---------|
| **论文数据获取** | 从 arXiv API 定期获取论文 | Python 脚本 + 定时任务 |
| **资讯搜索** | RSS 订阅获取相关资讯 | RSS 解析 + 内容分析 |
| **实体识别** | GLM 自动抽取作者、机构、研究方向 | GLM-5.2 API |
| **关系抽取** | 建立 4 种直接关系（论文合作、项目合作、师兄弟、顾问） | 基于实体自动推导 |
| **证据链处理** | 为每个关系建立证据链 | 证据表存储追溯 |
| **图谱可视化** | 支持大规模节点的交互式图谱展示 | React Flow / Cytoscape.js |
| **搜索功能** | 按姓名、机构、研究方向搜索 | PostgreSQL 全文搜索 |
| **手动编辑** | 人工修正实体和关系 | React 编辑界面 |

### 后续迭代功能

- 智能推荐：基于关系网络推荐潜在合作方
- AI 问答：自然语言查询关系网络
- 企业关系：挖掘校企合作关系
- 动态监控：实时关系变化提醒

## 技术先进性

### 1. 知识图谱 + 本体建模

**创新点**：基于本体的学术网络建模

- 以"人"为中心实体，其他实体围绕展开
- 关系本身是实体，有独立的属性和证据
- 支持 4 种专门的直接关系类型，每种都有专门的置信度评估

**技术优势**：
- 关系可追溯、可验证
- 支持复杂的网络分析
- 灵活的关系类型扩展

### 2. GLM 驱动的智能抽取

**创新点**：使用 GLM-5.2 进行全量实体和关系抽取

- 每篇论文都调用 GLM 进行实体识别和关系抽取
- 支持 4 种专门的关系抽取模式
- 输出结构化的 JSON 数据

**技术优势**：
- 准确度远高于传统规则方法
- 处理复杂的语义关系
- 支持多语言、多格式

### 3. 多维度置信度评估

**创新点**：每种关系都有专门的置信度计算方式

- **论文合作**：基于姓名确信度和机构确信度
- **项目合作**：基于信息明确性、充分性、可访问性
- **师兄弟关系**：基于数据源可信度、关系推断确定性
- **顾问关系**：基于信息明确性、时效性

**技术优势**：
- 量化关系可靠性
- 支持过滤和排序
- 降低决策风险

### 4. 证据链追溯机制

**创新点**：先有证据 → 识别关系 → 提取保存证据

- 每个关系都关联证据列表
- 支持证据的可追溯性
- 提供人类可读的证据描述

**技术优势**：
- 关系可靠性高
- 支持人工审核
- 增强决策可信度

## 目标用户

### 主要用户

- **技术合作经理**：寻找校企合作方，评估合作潜力
- **科研管理人员**：了解学术合作网络，分析合作动态
- **高校研究人员**：发现潜在合作伙伴，了解研究趋势

### 使用场景

**场景 1：寻找某领域的专家**
- 输入：技术领域关键词（如"Transformer"）
- 输出：该领域的专家列表 + 研究方向 + 合作关系

**场景 2：了解专家的合作网络**
- 输入：专家姓名
- 输出：该专家的合作者列表 + 合作论文 + 证据链

**场景 3：发现潜在合作机会**
- 输入：当前合作网络
- 输出：潜在合作方候选 + 置信度评估

## 技术架构

### 技术栈

| 组件 | 技术选型 | 说明 |
|-----|---------|------|
| **数据库** | PostgreSQL | 成熟稳定，支持 JSON 类型 |
| **后端框架** | FastAPI（Python） | 轻量高效，适合 AI 集成 |
| **前端框架** | React | 组件化开发，生态丰富 |
| **图谱可视化** | React Flow / Cytoscape.js | 支持大规模节点展示 |
| **AI 引擎** | GLM-5.2 API | 实体识别、关系抽取 |

### 系统架构

```
数据源层：论文数据库、RSS 资讯、高校官网
    ↓
AI 处理层：GLM 实体识别、关系抽取、置信度评估
    ↓
知识图谱层：PostgreSQL（实体 + 关系 + 证据）
    ↓
服务层：FastAPI 后端服务
    ↓
展示层：React 前端 + 图谱可视化
```

## 快速开始

### 环境要求

- Python 3.10+
- Node.js 18+
- PostgreSQL 14+

### 安装步骤

```bash
# 克隆项目
git clone https://github.com/waixiaoyu/prof-graph.git
cd prof-graph

# 安装后端依赖
pip install -r requirements.txt

# 安装前端依赖
cd frontend
npm install

# 配置环境变量
cp .env.example .env
# 编辑 .env 文件，配置 GLM API Key 和数据库连接

# 启动后端服务
python main.py

# 启动前端服务
npm start
```

### 配置说明

主要环境变量：

```bash
# GLM API 配置
GLM_CODING_API_KEY=your_glm_api_key
GLM_CODING_MODEL=glm-5.2

# 数据库配置
DATABASE_URL=postgresql://user:password@localhost:5432/prof_graph
```
